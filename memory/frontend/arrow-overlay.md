# The arrow overlay reads the DOM and never re-renders a card

Decided 2026-10-25.

**Decision:** `ArrowOverlay` (`arrow-overlay.tsx`) is one SVG inside the state pane that finds what to join through data attributes: `data-card` on each card, `data-arrow-to` on each `●` (`RefLabel`), `data-addr` on pointer labels. It measures with `getBoundingClientRect`, routes with the pure `route` (`arrows.ts`) and draws. Hover and focus are delegated listeners on the pane, and the highlight is a `data-active` attribute the overlay sets on the card and its labels directly, styled with `data-active:` utilities. A new layout (a step, or a setting that changes what is drawn) redraws in a layout effect, before paint; scroll, resize and divider drag (a `ResizeObserver` on the pane) redraw once per animation frame. Only what is on screen is measured: cards and stack labels are each one column in document order, so a binary search finds the visible slice, and labels inside an offscreen card are skipped.

**Why:** cards are `memo` with comparators that check exactly what they draw ([state-pane-skips-unchanged](state-pane-skips-unchanged.md)). Passing the hovered id or any geometry through props would re-render every card on hover and break the 4 ms step. Measuring every label and card each step cost 12 ms p50 at 4× CPU throttle on `synthetic-5000`; the visible slice costs 1.4 ms (S3, [plans/spikes/s3-arrow-overlay.md](../../plans/spikes/s3-arrow-overlay.md)). Measuring inside a `content-visibility: auto` card that is offscreen forces its layout, which is what the property saves.

**How to apply:** a view that draws a reference must render `RefLabel` (or keep its `data-arrow-to`), and a card must keep `data-card` on its root, or arrows silently stop for it. Keep cards in one vertical column and frames in another; a layout that puts cards side by side breaks the binary search, so change `onscreen` with it. Don't move hover state into the store or into card props. Measure overlay changes on a production build with `plans/spikes/s3/run.mjs`.
